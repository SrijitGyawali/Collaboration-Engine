## Key ideas

- **One rule fixes concurrent inserts.** Characters inserted after the same parent are kept sorted by ID, highest first. A local insert always has the highest ID its replica has seen, so it still lands right where the user typed. Concurrent inserts are sorted the same way everywhere, whatever order they arrived in.
- **The classic conflict.** Both users see "Hi" and insert after "H" at once: Alice X (`3@alice`), Bob Y (`3@bob`). Equal counters, so the replica name decides: `3@bob` sorts higher and comes first. Both replicas show "HYXi".
- **Why tombstones.** If Alice deletes "b" while Bob types "XY" after it, Bob's insert still needs "b" to exist when it arrives. So deletes only hide a character. Result on both replicas: "aXYc".
- **Deletes are safe to repeat.** Deleting twice, or both users deleting the same character, gives the same text.
