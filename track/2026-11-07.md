## How an edit travels

```text
Tab A: user types "!" ─▶ diffText(old, new, caret) = {pos 8, insert "!"}
       ─▶ CollabSession.applyLocal ─▶ CRDT insertText ─▶ op {kind: insert, after: ...}
       ─▶ BroadcastChannel "collab-engine:<doc>"
Tab B: CollabSession applies the op ─▶ positionOf(op.id) = 8
       ─▶ RemoteUpdate {text, changes: [{pos 8, insert "!"}]}
       ─▶ TextareaBinding moves B's caret through the change, then shows the text
```

## Key ideas

- **Two ways to count.** A textarea counts UTF-16 units and the CRDT counts characters, so `"👋"` is 2 in one and 1 in the other. Every position is converted at the boundary.
- **A textarea only says "here is the new text".** The edit is recovered by stripping the common prefix and suffix. Typing "a" into "a|a" is ambiguous, so the caret decides which "a" is new.
- **The caret must follow the text.** When someone types before your caret, your caret moves right with the text. A remote insert exactly at the caret goes after it, so two people typing at the same spot each keep their words together.
- **Exact when possible, fallback when not.** For every remote op the session reports exactly where it landed. If ops had to wait in the pending buffer, it reports "unknown", and the editor compares old and new text instead.
- **New tabs catch up by asking.** A new tab says hello, and open tabs answer with every op they have. Duplicates are harmless, so several tabs answering is safe.
- **Input methods.** Japanese, Chinese and Korean typing builds text in steps. Nothing is sent until the text is committed, and remote edits wait so the input method is not interrupted.

## Bugs found and fixed

- **IME text in the wrong place.** If another tab typed before the composition point while the user was composing, the committed text landed in the wrong spot (`">漢> ab"` instead of `">> a漢b"`). Found by a test written while reviewing the code. Fix: the committed edit is moved through the remote edits it missed.
- **Next.js 16 prerendering error.** With Cache Components, reading `searchParams` outside `<Suspense>` blocks prerendering. The page is now a static shell plus a streamed editor (partial prerender).
- **React lint rule.** The first editor component broke React's hooks rules. The binding moved into a plain class, which also made it testable without a browser.
- **Two test expectations were wrong**, not the code: the diff's tie-break without a caret, and the caret after a remote replacement. Both now match the rule the code implements.

## Known limits

- Undo (Ctrl+Z) is the browser's own and does not know about remote edits.
- A new tab is sent the full op log, which grows with every edit. The server will send only what is missing.
- Edits are not saved: closing every tab loses the document until Postgres arrives (Nov 8 to 10).
