## How the pieces connect

```text
CRDTDocument (TypeScript)       typed API; throws CRDTError
   │
RawDocument (globalThis.CollabCRDT)   returns {error} instead of throwing
   │  syscall/js
cmd/crdt-wasm (Go)              checks argument types, recovers panics
   │
internal/wire                   op <-> JSON / JS object, validates input
   │
internal/crdt                   the same CRDT the server will run
```

## Key ideas

- **One CRDT, two places.** The browser runs the Go library compiled to WebAssembly. There is no TypeScript copy that could merge differently.
- **One wire format.** An op is a plain object, such as `{"kind":"insert","id":{"counter":42,"replica":"alice"},"after":{...},"value":"X"}`. The same shape will be used on the WebSocket.
- **Errors as values across the boundary.** A panic inside a Go callback would kill the whole module. So the bridge type-checks every argument, recovers any panic, and returns `{error}`. TypeScript then throws.
- **JavaScript numbers are floats.** Counters above 2^53 would silently change, so the bridge rejects them, along with fractions and NaN.
- **Code points, not UTF-16.** In the CRDT, `"👋"` is one character, although `.length` in JavaScript says 2. The editor binding (Nov 7) must convert between the two.

## Problems found and fixed

- **Vitest would not install:** the generator pinned `@types/node` 20, but the project runs on Node 24 and Vitest 5 needs 22 or newer. Fixed by matching the types to the runtime, not by forcing the install.
- **ESLint failed:** it linted the copied `wasm_exec.js`, which is Go's code. It is now ignored.
- **Go saw npm code:** the npm package `flatted` ships a `.go` file, and `go list ./...` picked it up. An otherwise empty `web/go.mod` makes `web/` a separate module, which `./...` never enters.

## Checks

- Go: `internal/wire` at 100% coverage; `go vet`, `go test` and golangci-lint pass from the root.
- Web: 10 Vitest tests run the real module through JSON, including the "HYXi" conflict, early ops, duplicates and malformed input.
- Browser (`npm run dev`): the module loaded in 294 ms (50 ms cached); both replicas show "HYXi"; no console errors; the module is served as `application/wasm` with gzip, so the browser compiles it while it downloads; the page fits a 375 px screen.
