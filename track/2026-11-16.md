## The stack now

```text
browser ──▶ proxy :8080 ──┬──▶ gateway-a :8091 ──┐
           (Caddy)        └──▶ gateway-b :8092 ──┴──gRPC──▶ sync ──▶ PostgreSQL
                                   ▲        ▲                 │
                                   └────────┴──── Redis ◀─────┘
```

Browsers connect only to the proxy. Each gateway is also published on its own port, so a test can put two editors on different gateways on purpose instead of hoping the proxy splits them.

## The proxy

| Setting | Why |
| --- | --- |
| `lb_policy least_conn` | A WebSocket holds its gateway for a long time, so new connections go to the gateway with the fewest open ones |
| `lb_try_duration 5s` | If the chosen gateway refuses the connection (it is restarting), try the other one instead of failing the handshake |
| Health checks on `/healthz` every 2 s | A stopped gateway gets no new connections |
| No sticky sessions | Any gateway can serve any document: they all hear every edit through Redis |

## Tests

| Test | What it shows |
| --- | --- |
| Editors on two gateways converge (in-memory broker, and real Redis) | 4 clients split over 2 gateways make 60 random edits each at once and all end with the server's text |
| Cross-gateway edits arrive live | Each client opens exactly one connection, so edits crossed through Redis, not through catch-up |
| Gateway failover | A gateway shuts down mid-edit; its editor types offline, moves to the other gateway, and nothing is lost |
| Browser e2e, across two gateways | The TypeScript client on gateway A and on gateway B see each other live; 4 editors typing at once converge |

Testing the tests: with the gateway's pub/sub delivery switched off, all four new Go tests fail. With Redis stopped, the browser cross-gateway test fails.

## Checks on the running stack

- `make stack` starts everything and waits until it is healthy. One gateway image is shared by both gateways.
- Four WebSockets through the proxy split two and two (counted from the proxy's connections, minus one health-check connection per gateway).
- **A gateway stopped:** `gateway-b`'s two clients got `1001 server shutting down` through the proxy. `gateway-a`'s stayed connected. New connections through the proxy kept working, and `gateway-b` rejoined the rotation when started again.
- **Redis stopped:** new joins were turned away with "could not follow the document's edits", so clients retry instead of editing without hearing anyone. After Redis came back, everything passed again **without restarting anything**, because the gateways resubscribed on their own.
- Browser e2e: 4 of 4 pass through the proxy and directly against each gateway.
- Go: every package passes under the race detector; lint is clean. Web: type-check, lint, 131 unit tests.

## Key ideas

- **Stateless gateways make the proxy simple.** No sticky sessions, no shared state between gateways, just "fewest connections".
- **Test topology on purpose.** Going through the proxy, two editors might land on the same gateway and the test would pass for the wrong reason. Direct addresses remove the luck.
- **A lost Redis message is not lost data.** While Redis was down, edits were still stored. Clients get them back from their last `seq` when they reconnect.

## Known gap

A client that misses a Redis message without its connection dropping does not notice until it reconnects. Spotting the jump in `seq` and fetching what is missing is the plan for Nov 19. The gateway failover test already covers part of Nov 20 (killing a gateway mid-edit).
