## The contract

```text
service SyncService {
  ApplyOperations(doc, ops)        -> acks       one per op: seq, duplicate, error
  GetOperationsSince(doc, after)   -> stream     a page of ops per message
  GetSnapshot(doc)                 -> UNIMPLEMENTED until snapshots exist
}
```

## Key ideas

- **One contract, generated code.** Gateway and sync service share `sync.proto`. Both sides' Go code is generated from it, so they cannot disagree about a field.
- **Pinned generators.** The plugin versions live in `go.mod`, and buf is pinned in the Makefile. Everyone, including CI, generates identical code without installing anything.
- **Generated code is committed.** Builds and Docker images do not need buf. CI regenerates and fails if the result differs, which keeps the committed code honest.
- **Status codes tell the client what to do.** `InvalidArgument` means don't retry; `Unavailable` (for example the database is down) means retry later.
- **Graceful stop.** On shutdown, calls in flight may finish, so an edit being stored is never cut in half.
- **Testing gRPC without a port.** `bufconn` gives real gRPC over HTTP/2 in memory.

## Checks

- `syncrpc`: round trips through protobuf bytes; acks, duplicates and per-op rejection; a multi-page stream with exact seqs and limits; `InvalidArgument`, `Unimplemented` and `Unavailable`. All pass under the race detector.
- The sync binary on PostgreSQL, probed with a throwaway gRPC client: health `SERVING`, an insert stored as seq 1, a retry acked as a duplicate of seq 1, and the op streamed back.
- `make proto-check`: lint passes and the generated code matches.
