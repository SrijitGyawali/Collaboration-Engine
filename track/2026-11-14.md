## The integration tests

```text
Go clients ──WebSocket──▶ gateway ──gRPC (real TCP)──▶ sync service ──▶ memstore or PostgreSQL
```

| Test | What happens |
| --- | --- |
| Concurrent editors converge | 3 clients make 60 random edits each at the same time; all end with the server's exact text |
| The same on PostgreSQL | as above, storing in a real database |
| Reconnect catches up both ways | one client drops off; both sides keep editing; after reconnecting each has the other's edits |
| Sync service restart | the sync service dies mid-edit; the client keeps the unsaved edit; after a restart it is saved and everyone sees it |

Testing the test: with the gateway's broadcast removed, the convergence test fails at once.

## Key ideas

- **Test the real shape.** Nothing is mocked between the client and the database. The gRPC hop uses real TCP, so the sync service can be restarted on the same address.
- **The test client must behave like the browser.** A first version read the document length and then edited, so a remote delete in between broke it. A browser reads and edits on one thread, so the test client now does both under one lock.
- **Pings keep connections alive.** Proxies drop idle WebSockets after about a minute, and a sleeping laptop leaves a half-open connection. Pings every 30 s fix both.
- **A dead peer gets no goodbye.** Closing politely waits for the other side to answer, and an unresponsive client never will, so it is dropped immediately instead.
