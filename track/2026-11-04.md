## Key ideas

- **Example tests vs property tests.** An example test checks one case someone thought of. A property test states a rule ("all replicas converge") and checks it against hundreds of random histories.
- **Invariants catch bugs early.** Text can look right while the structure underneath is already broken. Checking the structure after every history finds a bug at the step that caused it.
- **Three properties.** Replicas converge; a replica's text depends only on which ops it has, not their order or repeats; a user's own edit appears exactly where they made it. The third matters because a CRDT that put every character at the end would also converge.
- **Testing the tests.** With the sibling order deliberately reversed, the convergence property fails from the first seed. That proves the test can catch a real bug.
- **Fuzzing.** Go's fuzzer mutates inputs and keeps the ones that reach new code. `FuzzApply` throws garbage at `Apply`; `FuzzSession` lets the fuzzer pick the whole editing history. A failing input is saved in `testdata/fuzz` and replayed by every later `go test`.
