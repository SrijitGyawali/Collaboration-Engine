## The system now

```text
browser ──WebSocket──▶ gateway ──gRPC──▶ sync ──▶ PostgreSQL
 :3000                  :8080            :9090     :15432 (operations + outbox)
                     (container)      (container) (container)
```

`make stack` builds and starts all of it: PostgreSQL, Redis, Redpanda, migrations, sync and gateway.

## Key ideas

- **Swap the backend, keep the code.** The gRPC client has the same two methods as the in-process service, so the gateway's WebSocket code did not change.
- **Stateless gateways.** With no store and no document state, any number of gateways can run side by side. Only cross-gateway broadcasting is missing (Redis, Nov 15).
- **Safe retries.** Every op has its own ID and repeats come back as duplicates, so the client retries `UNAVAILABLE` errors automatically (up to 4 attempts, 100 ms to 1 s).
- **Start-up order does not matter.** gRPC connects lazily and reconnects, so the gateway can start before the sync service, and the sync service can restart under a running gateway.
- **Small images.** Each service is a static binary on distroless: sync 29 MB, gateway 24 MB. There is no shell and no package manager, and it runs as non-root.
