## How presence works

```text
browser ──cursor──▶ gateway ──HSET + HPEXPIRE 30s──▶ Redis hash collab:doc:<id>:presence
                       │
                       └──PUBLISH {"type":"peer",...}──▶ collab:doc:<id>:ops ──▶ every gateway ──▶ other browsers
```

| Event | Gateway does | Browsers see |
| --- | --- | --- |
| Join | store + announce, then send `peers` (everyone already there) | a new name in "Also here" |
| Cursor move | store + announce `peer` with the cursor | the caret moves |
| Every 10 s | store again (TTL refreshed) + announce again | nothing changes |
| Leave | stop heartbeat, remove, announce `left` | the name and caret disappear |
| Gateway crash | nothing | entry expires in Redis after 30 s; browsers drop a peer silent for 30 s |

## Key ideas

- **A cursor is a character, not a number.** "Position 12" means something else as soon as someone types earlier in the text. The ID of the character before the caret never changes, so the caret stays put whatever arrives first. That needed `idAt` in the WebAssembly bridge.
- **TTL per field.** Redis 7.4+ expires single hash fields (`HPEXPIRE`), so one editor's entry expires on its own and the hash disappears with its last field. Write and expiry go in one transaction, so no entry exists without a TTL.
- **Announce, then list.** A joiner announces itself before reading who is there. Two people joining at once still hear about each other: each is already in the room, so the other's announcement reaches it live.
- **One channel for everything live.** Presence rides the edits' channel, so no new subscription logic was needed. The pub/sub package carries the bytes without knowing what they mean.
- **A reconnect is not a departure.** If an editor's new connection is already in the room when the old one closes, no `left` is sent.
- **Presence is best effort.** A failed store or publish is logged and fixed by the next heartbeat; it never drops the connection. A malformed cursor is ignored.

## Mistakes of mine

- **The first caret was 3.4 px too low.** The measuring span's box is the font's glyph area, not the line. The marker is now a zero-width character, and the bar is moved up to the line box.
- **A flaky test.** The heartbeat test used 40 ms beats, a 120 ms TTL. With the whole suite running it sometimes expired. It now uses 100 ms beats and passed ten runs under load.
- **An invisible character in the source.** A script wrote a real zero-width space into `caret.ts` instead of the `​` escape; replaced before committing.
